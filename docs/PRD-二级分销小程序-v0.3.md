# B2C 二级分销小程序 需求文档（PRD）

> 版本：v0.3（技术栈决策已并入）
> 日期：2026-11-16
> 平台：微信小程序（原生 JS + TDesign）+ 自建服务端（阿里云 ECS + Node.js + MySQL）
> 状态：决策已确认，可进入开发

---

## 1. 项目概述

### 1.1 项目定位
面向自有品牌的 B2C 分销型小程序商城。品牌方（平台）直接面向消费者销售少量自有 SKU（实物商品 + 虚拟服务），同时开放分销能力：普通消费者可成为推广者，通过分享链接/海报发展两级推荐关系，按订单逐级获取佣金。

### 1.2 核心目标
- 建立完整的「浏览 → 下单 → 支付 → 返佣」交易闭环
- 建立合规的两级分销关系链与佣金结算体系
- 通过分享裂变降低获客成本，提升复购

### 1.3 合规约束（红线，全案遵守）
| 约束 | 说明 |
|---|---|
| 分销层级 ≤ 2 级 | 佣金关系链最多「直接推广者 + 其上级」两层，不出现三级及以上返佣，规避传销风险 |
| 佣金来源为真实交易 | 佣金只从实际支付成功的订单利润中支出，不搞入门费、拉人头奖励 |
| 提现需实名 | 提现前完成微信实名信息收集，保留结算凭证 |
| 虚拟服务明示规则 | 虚拟商品不可退款部分需在购买页明示，避免纠纷 |

## 2. 用户角色

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 消费者 | 通过分享或搜索进入商城的用户 | 顺畅购物、支付、查订单 |
| 分销员（推广者） | 主动申请/自动开通分销资格的用户 | 分享赚佣金、看团队、提现 |
| 平台管理员 | 品牌方运营人员 | 管理商品、订单、佣金规则、提现审核、看数据 |

> 简化设计：消费者登录即自动生成分销资格（已确认，降低门槛）；管理员后台可手动封禁违规分销员。

## 3. 核心业务流程

### 3.1 推荐关系绑定
1. 分销员在小程序「分销中心」生成专属推广码（参数二维码 / 短链）
2. 新用户扫码或点击带参链接进入小程序
3. 系统记录参数中的推广者 ID，完成**首次绑定**并锁定关系（已确认：绑定后永久有效，不随分享变化）
4. 若新用户已被他人绑定，后绑定者不生效（先到先得）

### 3.2 下单返佣（逐级返佣规则）
- 用户 A 分享 → 用户 B 下单支付：A 获**一级佣金**
- B 分享 → 用户 C 下单支付：B 获一级佣金，A 获**二级佣金**
- 佣金基数 = 订单实付金额（扣除运费、优惠券分摊后的有效金额）
- 佣金比例：一级、二级在管理后台按商品（或全局默认）分别配置
- **结算时机**：订单确认收货后 + 售后期（默认 7 天）满 → 佣金由「冻结」转「可提现」；虚拟服务在服务核销/交付完成后结算（已确认：核销后结，规避退款坏账）

### 3.3 退款与佣金冲销
- 订单全额退款 → 对应冻结佣金全部作废
- 订单部分退款 → 按退款比例扣减冻结佣金
- 已提现后发生退款 → 从分销员可提现余额扣回，余额不足记「欠款」，冻结提现直至还清

### 3.4 提现流程
分销员申请提现 → 平台后台审核（金额、风控）→ 企业付款到微信零钱 → 短信/订阅消息通知
- 起提金额（建议 ¥10）、单日限额、手续费规则后台可配
- 依赖：微信支付商户号 + 商家转账到零钱能力（需企业/个体户资质）

## 5. 佣金规则详细设计

### 5.1 计算示例（后台可配比例）
- 商品实付 ¥100，一级佣金 10%、二级佣金 5%
- C（经 B 分享购买，B 的上级是 A）：B 得 ¥10，A 得 ¥5

### 5.2 边界规则
- 无上级的一级分销员成交：只发一级佣金，二级佣金归平台
- 自购返佣：默认**开启**（分销员自己下单也拿一级佣金），后台可关
- 佣金取整：保留两位小数，分摊按「实付比例」法，保证各分摊项之和 = 总优惠
- 佣金封顶：单笔订单佣金不超过商品毛利上限（后台可配），防止刷单套利
- 风控：同一用户高频自买自推、同一设备批量注册触发人工审核

## 6. 数据模型概要

| 数据表 | 关键字段 |
|---|---|
| users | openid、unionid、昵称、头像、inviter_id（直接上级）、inviter_path（≤2 级）、分销状态、实名的提现信息 |
| products | 标题、类型（实物/虚拟）、价格、库存、佣金一级比例、二级比例、状态、图片 |
| orders | 订单号、user_id、商品快照、实付金额、支付状态、售后状态、对应分销员链（buyer 的 inviter + inviter 的 inviter） |
| commissions | order_id、受益人、层级（1/2）、金额、状态（冻结/可提现/已提现/作废） |
| withdrawals | 分销员、金额、状态（待审/已打款/驳回）、转账单号 |
| relations | 绑定记录（被绑定人、绑定人、时间、来源参数码），用于审计防争议 |

## 8. 非功能需求

- **性能**：首屏加载 ≤ 2s，商品列表分页加载
- **安全**：佣金计算全部在服务端完成，前端不可传入佣金参数；支付回调验签 + 幂等；提现审核双人复核（可选）
- **一致性**：佣金状态流转与订单售后状态强关联，采用事务/幂等设计，防止重复结算
- **合规**：分销规则页面向用户明示层级与比例；用户数据收集遵循最小必要原则
