## 1. 全链路总览

```
┌─────────┐  ①分享(带 inviterId)  ┌─────────┐
│ 分销员 A │ ────────────────────▶ │ 微信会话 │
└─────────┘                       └────┬────┘
                                       │ ②B 点开卡片
                                       ▼
                              ┌──────────────────┐
                              │ 小程序启动         │
                              │ app.onLaunch 解析  │
                              │ scene/path 参数    │
                              └────┬─────────────┘
                                   │ ③静默登录 + 携参
                                   ▼
                        ┌─────────────────────────┐
                        │ POST /api/auth/login     │
                        │ { code, inviterId }      │
                        │ 服务端绑定事务：           │
                        │  · B 无上级 → 先到先得绑定 │
                        │  · B 已有上级 → 忽略参数   │
                        │  · 自绑/上级被封禁 → 忽略  │
                        └────┬────────────────────┘
                             │ ④B 浏览/下单
                             ▼
              ┌──────────────────────────────┐
              │ B 创建订单 → 微信支付          │
              │ 支付成功（回调 或 对账job兜底） │
              │ → markPaid 幂等落账           │
              └────┬─────────────────────┬───┘
                   │ ⑤同事务内生成佣金     │
                   ▼                     ▼
        ┌──────────────────┐   ┌──────────────────┐
        │ 实物订单 PAID      │   │ 虚拟订单 REDEEMED │
        │ → 佣金 FROZEN     │   │ → 佣金 AVAILABLE  │
        │ (售后期满结算)     │   │ (核销直结，不可退) │
        └────────┬─────────┘   └────────┬─────────┘
                 │ ⑥售后期(7天)满，        │
                 │   settleExpiredFrozen  │
                 ▼                        ▼
              AVAILABLE ──提现──▶ WITHDRAWING ──▶ PAID
```

## 2. 带参分享规则

| 项 | 规则 |
|---|---|
| 携带方式 | 分享 path 追加 `inviterId=<uid>`（如 `/pages/home/home?inviterId=12`）；后续可扩展海报 scene 码 |
| 参数有效性 | 仅当指向 `distributor_status=active` 的存量用户生效；无效/自绑参数**静默忽略**，不阻断登录 |
| 每人始终携带 | 所有分享场景（首页/详情/个人中心）统一由前端 utils 拼参，避免漏带 |

## 3. 绑定规则（先到先得，永久有效）

1. **时机**：仅在登录接口内完成（`POST /api/auth/login` 携 `inviterId`），其余接口一律不接受绑定参数——保证绑定与建号同事务、无并发窗口。
2. **先到先得**：`users.inviter_id IS NULL` 为唯一绑定窗口；绑定动作 = 写 `relations` 审计行 + 更新 `users.inviter_id`，同一 InnoDB 事务。并发场景由行锁保证只有第一个成功（PRD 决策 #2）。
3. **永久绑定**：绑定后任何后续分享不再改变归属关系；解绑/换绑本期不提供。
4. **层级边界**：关系链仅推导两级（买家→上级 L1→上上级 L2）；L2 的上级**不**参与返佣（三级即违规，硬编码边界）。
5. **防绕路**：买家自购同样按其关系链返佣（自己买、上级得佣）；A 分享给 B，B 再分享给 C——C 归属 B（L1），A 得 L2 佣金。

## 4. 佣金触发与归属判定

```
下单成功支付（PAID 或 REDEEMED）
   │
   ├─ resolveUplines(buyerId)：读 users.inviter_id 及其 inviter_id
   │    ├─ 有 L1 → 生成 L1 佣金（rate = 商品级覆盖 或 全局默认，单位 bp）
   │    ├─ 有 L2 → 生成 L2 佣金
   │    └─ 无上级 → 不生成（不补发）
   │
   ├─ 金额 = itemBaseCents(分摊后行实付) × rate_bp / 10000，整数分四舍五入
   │    同单 L1+L2 之和 ≤ 有效实付（扣运费与优惠分摊）
   │
   └─ 全程仅 services/commission.service.js 可写 commissions 表（铁律，§2.1）
```

- **实物商品**：PAID 时生成 `FROZEN`；订单 COMPLETED 且售后期（默认 7 天，configs 配置）满 → 结算 job 转 `AVAILABLE`；全额退款 → `VOID`。
- **虚拟服务**：核销（REDEEMED）时直接生成 `AVAILABLE`（无售后期，购买页已明示不可退，PRD 决策 #3）。
- **收款人资格**：生成佣金时分销员已被封禁（banned）→ 佣金仍生成但置 `FROZEN`，由后台人工裁决（防「先赚佣后封号」套利；后台裁决功能 M4 交付）。

## 5. 状态流转与对账锚点

状态机图见 architecture.md §4.2（唯一事实源）。本链路涉及的对账锚点：

| 锚点 | 规则 | 校验方 |
|---|---|---|
| 佣金条数 | 每笔有效订单 ≤2 条佣金，beneficiary 唯一 | 每日对账 job |
| 金额守恒 | Σ佣金 ≤ Σ有效实付；分摊基数与订单项金额一致 | 每日对账 job + 单测 |
| 结算时效 | FROZEN 且订单过售后期 → 必须已被 settleExpiredFrozen 处理 | 每小时结算 job |
| 幂等 | 生成以 order_id+level 唯一约束兜底，回调重放/对账重跑不重复生成 | 数据库约束 |

## 6. 合规明示（PRD §3.3 约束落地）

- 分销规则页（pages/rule）上线前必须展示：层级 ≤2 级、佣金比例、结算时效、退款冲销规则；
- 提现前需实名（real_name + id_card_no，AES 加密存储）——M3 提现模块实施；
- 全额退款且佣金已 PAID → 欠款冻结余额直至扣回（architecture.md §4.2 不变式 4）。
