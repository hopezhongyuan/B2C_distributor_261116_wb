# UI-SPEC — B2C 二级分销小程序 · 页面与组件规范

> 版本：v1.0（**已确认**，2026-11-17 全部决策点拍板，整改与后续开发依据）
> 适用：`admin-web`（Vue3 + TDesign Vue Next）、`miniprogram`（微信原生小程序）
> 强制等级：**MUST** 必须遵守 / **SHOULD** 建议遵守（偏离需说明理由）/ **MAY** 可选
> 方法论承袭自既有项目 UI-SPEC v1.4：**Token 收口、模板收口、验收收口**三道防线；按本项目技术栈（TDesign / 微信原生）与业务域（二级分销 / 资金审核）全面定制。

## 0. 现状诊断（为什么要立这份规范）

对现有两端的走查结论，以下问题即本规范要消除的反例：

| # | 症状 | 位置 | 成因 |
|---|---|---|---|
| 1 | 主色是 TDesign 默认蓝，与小程序无品牌关联，颜色随手写 | admin-web 全部页面 | 无 Token 层，样式散落在各 `.vue` 的 `<style>` |
| 2 | 页面无统一页头（标题+说明），有的有 t-card 标题有的没有 | 10 个后台页面 | 无页头模板约定 |
| 3 | 状态展示不统一：有的裸文本（PAID/FROZEN 英文裸奔已修但样式不一）、有的 t-tag 颜色随手配 | 订单/佣金/提现/退款 | 无状态→文案/颜色统一映射 |
| 4 | 金额格式两套写法（已统一到 utils/money.js，但视觉上无等宽数字、无正负色语义） | 后台 7 个视图 | 缺 ProMoney 层 |
| 5 | 表格密度不一、操作列是按钮非文字链接、无「更多」折叠 | 各列表页 | 无表格细则 |
| 6 | 小程序页面底色不一（有 #fff 有 #f6），按钮三四种写法，点击态用 opacity | miniprogram 多页 | 无 C 端 Token |
| 7 | 空态=空白表格，加载=转圈，无骨架屏 | 两端 | 无四态标准 |
| 8 | 看板指标卡风格朴素、无环比、图表无统一规则 | DataDashboard | 无看板模板 |

## 1. 设计原则（评审依据）

| # | 原则 | 含义 | 反例 |
|---|---|---|---|
| 1 | 一个页面一个主任务 | 一屏一个视觉焦点、一个主按钮 | 商品页同时放「新建/导出/上下架」三个同权重按钮 |
| 2 | 数字优先 | 经营数据右对齐、等宽数字、千分位、金额 2 位小数 | 佣金左对齐、`12.5` 与 `12.50` 混排 |
| 3 | 操作必有反馈 | 提交中禁用+loading，成功有提示，失败有原因和下一步 | 点「审核」无反应，用户连点 |
| 4 | 同类同构 | 同一种数据永远用同一种组件：状态一律彩签、金额一律 ProMoney | 订单状态列表用文字、详情用彩签 |
| 5 | 默认安全 | 资金操作二次确认，确认文案写清后果与不可逆性 | 「确定拒绝吗？」——不写退款将原路退回 |
| 6 | 克制用色 | 主色只用于关键动作与选中态，红色只属于价格/佣金/危险 | 每个卡片标题都用主色，整页发蓝 |
| 7 | 分销心智 | C 端让用户随时知道「我能赚多少」：可分佣商品必须露出收益提示 | 商品详情只展示售价，分销员看不到推广收益 |

### 2.1 色彩

**已确认：主色靛蓝 + 价格红，主色与危险色分离。**

| 用途 | Token | 色值 | 说明 |
|---|---|---|---|
| 主色 | `--c-primary` | `#2B5CE6` | admin 与小程序**共用**，建立跨端品牌一致 |
| 主色 hover / active | `--c-primary-hover` / `-active` | `#1E4ED8` / `#1A3FB0` | |
| 主色浅底 / 描边 | `--c-primary-bg` / `-border` | `#EEF3FF` / `#C7D7FB` | 选中态、信息条 |
| 强调色（价格/佣金/收益） | `--c-accent` | `#D93A3A` | 售价、佣金金额、分销收益提示 |

| `--t-2` | `#5A6472` | 正文、表格内容 |

### 2.2 字体与字号

- 字体栈：`-apple-system, "PingFang SC", "Microsoft YaHei", Inter, sans-serif`
- 所有金额/数量/统计数字 MUST `font-variant-numeric: tabular-nums`
- 一屏字号 ≤ 3 种（数字展示页除外）

| 层级 | admin (px/字重) | 小程序 (rpx/字重) | 用途 |
|---|---|---|---|
| 大屏数字 | 32/600 | 56/600 | 看板核心指标、分销中心累计佣金 |
| 指标数字 | 24/600 | 40/600 | 统计卡主数值 |
| 页面标题 | 20/600 | 36/600 | 页头 / 导航栏标题 |
| 卡片标题 | 16/600 | 30/600 | 卡片、弹窗标题 |
| 正文 | 14/400 | 28/400 | 表单、表格、段落 |
| 表格正文 | 13/400 | — | 数据密集表格 |
| 辅助 | 12/400 | 24/400 | 说明、时间、表头 |
| 极小 | — | 22/400 | 角标、法规文案 |

### 2.3 间距 / 圆角 / 阴影

- 间距基准 4，档位只允许 `4/8/12/16/20/24/32/40/48/64`（小程序为对应 rpx 值 `8/16/24/32/40/48/64/80/96/128`）
- 圆角四档：`4`(输入框/按钮/标签)、`8`(卡片/表格容器)、`12`(弹窗/移动端卡片，小程序 `24rpx`)、`999`(胶囊/头像)
- 阴影三档：卡片 `0 1px 2px rgba(16,24,40,.04)`、hover/下拉 `0 4px 12px rgba(16,24,40,.08)`、弹窗 `0 12px 32px rgba(16,24,40,.14)`
- 同层级不叠加阴影+描边，卡片选其一（**后台卡片统一：描边 1px `--line` + sh-1**）
- 动效：hover 120ms ease-out；展开/下拉 200ms；弹层 300ms；禁止 >400ms 过渡与装饰性弹跳

### 2.4 暗色模式 **不做**（已确认）

## 3. 后台页面规范（admin-web / TDesign）

### 3.1 整体框架

```
┌──────────┬─────────────────────────────────────────────┐
│  侧边栏   │ 顶栏 56：面包屑 ················· 账号/角色   │
│  200px   ├─────────────────────────────────────────────┤
│  菜单10项 │ 页头：标题 20/600 + 一句说明（这页能做什么）     │
│  分3组   │ ───────────────────────────────────────────  │
│          │ 内容区 bg-page, padding 20                    │
│          │ ┌─────────────────────────────────────────┐ │
│          │ │ 卡片：白底 r-8 描边 sh-1 padding 20        │ │
│          │ └─────────────────────────────────────────┘ │
└──────────┴─────────────────────────────────────────────┘
```

- 菜单分组（现有 10 项按域归组）：**交易**（商品/订单/退款）、**分销**（分销员/绑定/佣金/提现）、**平台**（看板/参数/日志）
- 当前项：文字主色 + 浅底 + 左侧 3px 主色条
- 页头为每页 MUST 结构；页头不放统计数字（数字属于看板）
- **TDesign 覆盖策略**：只经 CSS 变量（`--td-brand-color` 系列、`--td-radius-*`、`--td-comp-*`）在 `styles/td-override.css` 收口，不改组件源码、不用 `!important`

### 3.2 页面模板映射（现有 10 页全部归入五模板）

| 模板 | 页面 | 结构 |
|---|---|---|
| **列表页** | 订单、商品、退款审核、提现审核、分销员、绑定查询、佣金、操作日志 | 页头 → 筛选条 → 表格 → 分页 |
| **详情类** | 订单详情（弹窗/抽屉承载） | 概览卡 + 分组信息 + 关联流水 |
| **表单/配置页** | 参数配置、商品编辑（弹窗表单） | 分组卡片 + 吸底操作条 |
| **看板页** | 数据看板 | 指标卡行(4) → 图表区(2:1) |
| **登录页** | AdminLogin | 独立模板，见 3.6 |

### 3.3 列表页细则（MUST）

**筛选条**：单行 ≤4 条件；「查询/重置」固定右侧，`Enter` 触发查询；宽度输入 200 / 下拉 160 / 日期 240；筛选随路由 query 持久化（刷新/后退不丢）。

**表格**

| 项 | 规则 |
|---|---|
| 行高 | 统一 **44px**，表头同 44（已确认） |
| 表头 | 底 `--bg-muted`，12/500 `--t-3`，无竖线 |
| 分隔 | 仅 1px 横线 `--line-light`；**无斑马纹**；hover 行 `--bg-hover` |
| 对齐 | 文本左、**数字右**、状态居中、时间左 |
| 空值 | 统一 `—`，禁止空白单元格（`fmtCols` 已有雏形，收口进 ProTable） |
| 长文本 | 单行省略 + tooltip |
| 商品图 | 32×32，r-4，缺失显示商品名首字占位 |

**行操作项**（文字链接 `theme="primary"` 13px，≤3 个，超出进「更多」；危险项沉底；无权限 `v-if` 不渲染；状态不满足置灰+tooltip；执行中该行 loading）

| 页面 | 行操作（左→右） | 「更多」 |
|---|---|---|
| 订单 | 详情、核销（虚拟+PAID 时） | 复制订单号、复制交易号 |
| 商品 | 编辑、上架/下架 | —（新增为页头主按钮） |
| 退款 | 审核（PENDING）/ 详情（已处理） | 重试打款（FAILED 且 finance） |
| 提现 | 审核（pending）/ 同步打款（approved） | 复制单号 |
| 分销员 | 详情、启用/禁用 | — |
| 绑定 | —（纯审计查询，不提供操作） | — |
| 佣金 | 详情（按订单跳转） | — |
| 日志 | —（摘要列已含全部信息） | — |

**批量操作**（已确认）：v1 开启**商品页**（批量上下架）与**订单列表页**（批量关闭待支付订单：仅 `PENDING_PAY` 可勾选，其余状态行禁用勾选；批量条显示已选数量+「关闭选中订单」危险按钮，确认弹窗写明后果）。**提现审核、退款审核永久禁止批量**（资金红线：必须逐笔核对金额与凭证，不接受效率理由）。其余页面不做多选。

**分页**：右下角，默认 20，可选 20/50/100，显示总数；翻页后滚动至表格顶部。

### 3.4 表单细则（MUST）

- 标签右对齐宽 96；必填红星前置；`blur` 校验格式、提交全量校验并聚焦首个错误
- 每卡片 ≤8 字段；底部操作条 sticky，取消左、主按钮右；提交中 loading+全表单禁用
- **金额输入**（商品价格、提现金额展示）：统一「元」单位、2 位小数、min 0；校验文案写清范围（「起提金额需 ≥ 10.00 元」）
- 危险确认弹窗：标题写动作（「拒绝退款」），正文写对象与后果（「订单 20261xxx 将全额退款并冲销佣金，不可恢复」），按钮写结果（「确认拒绝」）
- 弹窗宽度：纯确认 480；4–10 字段/需看背景数据用抽屉 560

### 3.5 数据展示与状态色映射（统一走 `ProStatusTag`）

金额：千分位+2 位小数，单元格不带单位（单位在表头）；负数危险色；百分比 1 位小数；时间 `YYYY-MM-DD HH:mm`；空值 `—`；订单号 hover 可复制。

| 域 | 状态 → 颜色 |
|---|---|
| 订单 | PENDING_PAY 警告橙 / PAID 主色蓝 / DELIVERED 信息浅蓝 / COMPLETED·REDEEMED 成功绿 / REFUNDING·PARTIAL_REFUNDED 警告橙 / REFUNDED·CLOSED 中性灰 |
| 佣金 | FROZEN 灰 / AVAILABLE 绿 / WITHDRAWING 橙 / PAID 蓝 / VOID 灰删除线 |
| 退款 | PENDING 橙 / APPROVED 蓝 / REFUNDED 绿 / REJECTED 红 / FAILED 红 |
| 提现 | pending 橙 / approved 蓝 / paid 绿 / rejected·failed 红 |
| 商品 | draft 灰 / on 绿 / off 橙 |
| 分销员 | active 绿 / banned 红 |

图表：网格线 `--line-light` 虚线仅横向；Y 轴无轴线；tooltip 白底 sh-2 r-8 数值右对齐；区间无数据显示「所选区间暂无数据」不画空坐标系；金额超 1 万切「万元」并标注。

### 3.6 看板与登录页

- **看板**：4 指标卡（等高 108：GMV / 订单数 / 分销员数 / 佣金支出比）数值 24/600 前置 `¥` + 环比 12；下方 2:1 分栏（销售趋势折线 : 漏斗/待办）；图表卡高统一 320
- **登录页**：居中卡片 400 宽、r-12、sh-3；顶部品牌区（产品名+主色 logo 占位）；输入框 40 高；登录按钮主色通栏 40 高；错误提示卡片顶部信息条（不用 alert 弹窗）；锁定状态下倒计时展示

### 3.7 四态标准（所有数据页 MUST）

| 状态 | 视觉 | 文案模板 |
|---|---|---|
| 加载 | 骨架屏（表格 5 行骨架，**不用转圈**） | — |
| 空 | 轻量插画 + 一句说明 + 主操作 | 「还没有订单」「订单会在用户下单后出现在这里」；筛选无结果须区分：「没有符合条件的订单」+「清空筛选」 |
| 错误 | 图标 + 原因 + 重试 | 「加载失败，请检查网络后重试」 |
| 无权限 | 锁图标 | 「当前账号无权查看，请联系管理员」 |

## 4. 后台组件规范

### 4.1 分层与边界

```
styles/tokens.css          # 唯一色值/字号/间距来源（含 TDesign 变量覆盖）
components/base/           # Pro* 基础组件：只解决一致性与默认值
components/business/       # 业务组件：只解决复用与业务规则展示
views/                     # 只负责取数、编排、跳转
```

- 页面 MUST NOT 直接写超 5 个属性的 `t-table` 配置 → 用 `ProTable`
- 业务组件 MUST NOT 直接调接口；Base 组件 MUST NOT 出现业务文案
- 单文件超 200 行必须拆分（项目 AGENTS.md §4 硬门禁，**优先于参考规范的 300 行**）

### 4.2 基础组件清单（9 个）

| 组件 | 解决什么 | 关键 props |
|---|---|---|
| `ProTable` | 服务端分页、列定义、行操作折叠、四态、空值兜底 `—` | `columns` `fetch` `rowActions` `defaultPageSize` `emptyType` |
| `ProPageHeader` | 标题 + 说明 + 右侧操作区 | `title` `description` |
| `ProStatusTag` | 状态值→文案/颜色统一映射（§3.5 表为唯一来源） | `domain` `value` |
| `ProMoney` | 分→元、千分位、2 位小数、正负色、空值 `—` | `cents` `showSign` `size` |
| `ProEmpty` | 空/筛选无结果/错误/无权限四态 | `type` `description` |
| `ProSkeleton` | 表格/卡片/详情骨架 | `type` `rows` |
| `ProConfirm` | 危险确认弹窗（动作标题+后果正文+结果按钮） | `title` `content` `confirmText` `danger` |
| `ProDescriptions` | 详情分组只读展示 | `items` `column` `title` |
| `ProFilterBar` | 筛选条件+查询/重置+Enter+路由持久化 | `fields` `model` |

### 4.3 业务组件清单（6 个，按本项目业务）

| 组件 | 用途 | 关键点 |
|---|---|---|
| `OrderStatusTag` | 订单 9 态彩签（封装 ProStatusTag 域） | 含虚拟单 REDEEMED 语义 |
| `CommissionFlowItem` | 佣金流水行：受益人+级别(L1/L2 徽标)+比例+金额+状态 | VOID 态删除线 |
| `FundAuditDialog` | 退款/提现审核共用弹窗 | 见下 |
| `RelationTree` | 分销员详情两级团队树 | l1/l2 分组、via 邀请路径 |
| `StatCard` | 看板指标卡 | 主数值+环比+口径 tooltip |
| `SpecEditor` | 商品规格标签编辑 | 逗号分隔输入 → tag 列表，去重校验 |

**FundAuditDialog 内部规则（资金红线落地）**：
- 退款：显示订单实付、申请金额、原因、下单人；「拒绝」备注必填 ≥2 字；「通过」前**必须勾选**「已核对退款金额与订单实付」；通过后提示「退款将原路退回，佣金按比例冲销」
- 提现：收款信息（实名+掩码身份证）每行一键复制；「同意打款」前必须勾选「已完成线下打款核对」；拒绝备注必填
- 审核结果与备注自动写入操作日志（auditLog 中间件已支持）

## 5. 小程序页面规范（微信原生 / rpx）

### 5.1 基础

- 设计基准 375（`1px = 2rpx`）；页面底色统一 `#F5F7FA`；卡片白底 r-24rpx 描边无阴影，卡片间距 24rpx，卡片内边距 32rpx
- 价格/佣金/收益一律强调色 `#D93A3A`：整数 40rpx/600、小数 28rpx/600、符号 28rpx
- 底部安全区：`padding-bottom: calc(20rpx + env(safe-area-inset-bottom))`；吸底操作条高 `120rpx`+安全区，主按钮占 60% 宽
- 点击态：背景色变 `#F2F4F7`（hover-class），**禁止整块 opacity**
- 图片 MUST `mode="aspectFill"` + 固定宽高；可点区域 ≥ 88rpx；弹层锁滚动
- 主色与后台一致 `#2B5CE6`（tabBar 选中色、链接、主按钮）

### 5.2 页面结构映射（14 页）

| 页面 | 结构规范 |
|---|---|

## 6. 体验清单（上线前逐条打勾）

**反馈**：异步按钮 loading+disabled；写操作成功 toast 2s / 失败 toast 4s 含原因；删除/审核/退款二次确认写后果；骨架屏首屏、表格 loading 翻页；行操作按状态生成无「必报错」按钮；资金审核有勾选闸门。

**导航**：详情返回列表保留筛选与页码；弹窗关闭焦点回触发按钮；401 跳登录带 redirect 回原页（**已实现**）。

**表单**：提交前校验并聚焦首错；金额/手机号格式提示写清正确格式；提交成功给「下一步」。

**移动端**：首屏骨架；图片固定宽高；吸底不挡安全区；弹层锁滚动；`adjust-position` 防键盘遮挡；可点区域 ≥88rpx。
